# 里程碑、验收与指标（百万行规模）

> 本文件是 [DEVELOPMENT-PLAN.md](../DEVELOPMENT-PLAN.md) §12–§13 的附件：**每个里程碑必须能演示一个「拒绝」，并在规模上留下数据。**
> 指标在 M0 冻结；pilot 前不改，变更需在 DECISIONS 记录。

---

## 一、里程碑与退出条件

| 阶段 | 时长 | 目标 | 退出条件（可验收） |
|---|---|---|---|
| **M0** | 2 周 | 决定、基线、骨架、契约 | 骨架可加载；V5 归档；引文台账可复现；policy/receipt/registry schema 定稿；指标冻结 |
| **M1** | 4 周 | 单团队试点（1 子系统） | ≥50 PR 走 L0/L1；回执校验通过；自签=0；误拦<5%；成本达标 |
| **M2** | 4 周 | L2 路径与影响分析 v1，正确性论证 v0 | ≥10 个 L2；影响召回 ≥90%（标注集）；双模型席位；correctness case 映射完整；人签记录 |
| **M3** | 4 周 | CI 强制与度量 | PR 因缺证据/过期被拦；回执完整率 ≥95%；看板可用；采样生效 |
| **M4** | 6–8 周 | 规模试点 | ≥1M LOC 或代表性仓库；3 团队；200+ PR；误拦<2%；成本 ≤3×；时延达标 |
| **M5** | 4 周 | 组织推广 | 采纳 ≥80%；例外 <5%；playbook/培训/策略模板齐备；go/no-go |

## 二、各阶段交付

### M0（2 周）

- D1–D8 决策定稿（[DECISIONS.md](DECISIONS.md)）。
- V5 归档 tag + hash；引文台账可复现。
- 仓库骨架：7 个工具（stub）、6 个技能占位、`lib/json.js`、`lib/tiers.js`。
- **规模契约**：`policy.schema.json`、`subsystems.schema.json`、`interfaces.schema.json`、`receipt.schema.json`。
- 指标冻结 + tag `metrics-v0`。
- 风险登记册 + 红队意见。

### M1（4 周）单团队试点

- `firetree_classify`、`firetree_assess`、`firetree_hypothesis`、`firetree_receipt`、`firetree_state`。
- 子系统注册表 + CODEOWNERS 解析；L0/L1 分级。
- 回执最小校验：证据生产者、签字人、等级要求。
- 技能：`firetree`、`firetree-assess`、`firetree-receipt`。
- 验收：50 个真实 PR；误拦 <5%；单 PR 成本在预算内；团队愿意继续。

### M2（4 周）L2 与影响分析

- `firetree_review`、`firetree_synthesize`、`firetree_hypothesis` 抽样验证。
- 接口注册表 + 影响分析 v1（未知即 L2）。
- L2 路径：双模型席位、七步、人签。
- 验收：10 个 L2；影响召回 ≥90%（50 条标注集）；七步缺步被拒；自签被拒。

### M3（4 周）CI 强制与度量

- CI 证据 bundle + 回执生成；OIDC 身份；PR 必需检查；分支保护模板。
- 过期/缺证据阻断；采样决定入回执。
- 事件流 + 聚合 + 看板（逃逸/时延/L2 占比/误拦/成本）。
- 验收：删除证据 → PR 失败；改过期时间 → 拒绝；看板可用。

### M4（6–8 周）规模试点

- 目标仓库：≥1M LOC 或代表性（10k+ 文件）；3 团队；200+ PR。
- 准实验设计：匹配子系统 + 中断时间序列（见 §四）。
- 验收：误拦<2%；成本 ≤3×；时延 SLO；逃逸率方向性改善；复盘报告。

### M5（4 周）组织推广

- Playbook、策略模板、例外流程、培训材料。
- 采纳 ≥80%；例外 <5%；go/no-go 决策。

## 三、预注册指标（metrics-v0）

> **冻结记录**：2026-11-06 冻结为 `metrics-v0`，tag `metrics-v0`。pilot 前不改定义、口径、阈值或停止规则；任何变更必须先在 [DECISIONS.md](DECISIONS.md) 记录并重新打 tag。
> **样本不足时只报告效应量与方向性，不做强因果断言。**

### 3.1 主要指标（决定去留）

| 指标 | 定义 | 采集 | 阈值（冻结） |
|---|---|---|---|
| 逃逸缺陷率 | 合并后 30 天内归因于该变更的缺陷数 / 100 行改动 | 议题 + 归因 + CODEOWNERS 确认 | M4：D 相对 B 下降 ≥20%；12 个月目标：≥30% |
| 评审精确率 | 被采纳发现 / 上报发现 | 回执 + 评审记录 | ≥60%，且不低于 B |
| 返工率 | 评审后新增提交数 / 变更 | git | ≤1.2× B |
| 周期时间 | 首提交 → 合并 | git | ≤1.5× B |

- B = 纯 DSH agent（无技能、无工具、无闸门）；C = B + 四机制（本地证据 A1）；D = C + CI/PR 强制（A2）。
- M4 的 ≥20% 是去留阈值；12 个月的 ≥30% 是能力目标。两者不得合并或互相替代。
- 主要指标的效应估计以 PR/变更为单位，报告相对变化与 95% bootstrap 置信区间。

### 3.2 规模指标（决定能否推广）

| 指标 | 定义 | 目标 |
|---|---|---|
| 回执完整率 | 有效回执 / 应回执变更 | ≥95% |
| 回执校验时延 | `firetree_receipt check` 的校验耗时 | ≤2s |
| 正确性论证完整率 | L2 中「每条 claim 至少映射一个 invariant 与一条 evidence，且 residual 已人签未过期」的 claim 比例 | ≥95% |
| 误拦率 | 协议误拦 / 总拦截 | M1 <5%；M4 <2% |
| L2 占比 | L2 / 全部变更 | ≤15% |
| 例外率 | 例外 / 变更，且全部有到期日 | <5% |
| 单 PR 成本 | tokens / 变更（分层） | L0≤20k、L1≤100k、L2≤400k |
| 评审时延 | open → verdict | L0 当天、L1≤1d、L2≤3d |
| 自签数 | agent 作为 producer 或 signoff 的次数 | 恒 0 |
| 橡皮图章率 | <10s 且 approve 的签字占比 | <80% |

- **正确性论证完整率不改变单条拒绝规则**：任何 L2 空映射或未签残差仍逐条拒绝；≥95% 是流程质量指标，不是放行阈值。
- **误拦**只统计「按协议被拒绝、复核后确认不应拒绝」的 PR；因证据缺失被拒且复核确认缺失的不算误拦。
- **L2 占比**按周滚动统计；连续 4 周 >15% 触发分级策略复盘，不得用降级解决。
- token 由宿主提供；宿主不提供时按「调用次数 × 估算」记录并标记 `estimated=true`。

### 3.3 样本量与统计口径

| 项 | 冻结口径 |
|---|---|
| M4 样本 | ≥200 个真实 PR、≥3 个团队、匹配子系统；启用前后各 ≥8 周 |
| 最小可报告样本 | 若 <200 PR 或无法匹配子系统，只报告方向性与效应量，标注「样本不足，不作因果断言」 |
| 归因窗口 | 合并后 30 天；跨窗口缺陷在发现时回填，不追改历史报告 |
| 基线 | B 组的启用前 8 周 + 匹配子系统同期；优先使用中断时间序列 |
| 聚合 | 按周聚合；主指标按 PR 级配对或匹配后汇总 |
| 隐私 | 仅记录 issue/PR id、tier、team、tokens、时长、轮次、结果；不含代码内容、密钥、个人信息 |

### 3.4 停止规则（与 §五 同步，冻结）

| 触发 | 动作 |
|---|---|
| C/D 相对 B 在逃逸缺陷率上无 ≥20% 改善，或精确率低于 B | 停止扩机制；保留有效子集 |
| 成本 >5× B 且无主要指标改善 | 收缩或停止；发布方法与数据 |
| 误拦 M1 >5% 或 M4 >2% | 先修分级/影响分析，不扩机制 |
| 评审时延连续 2 周超 SLO（L1>1d / L2>3d） | 加评审人、调采样或 WIP；不得把 L2 降级 |
| L2 连续 4 周 >15% | 复盘分级策略，不允许降级 |
| 自签数 >0 | 立即停止 pilot，修证据/签字路径 |
| 影响同类漏报 2 次 | 该路径强制 L2 并补注册表 |
| 人签从未改变决定（>95% 且 <10s） | 重设计签字点或降级为抽样审计 |

### 3.5 禁止指标

LOC、发现数、评审轮数、技能数量——古德哈特风险。

## 四、评估设计（准实验，不是 RCT）

百万行项目无法做随机对照，采用：

1. **匹配子系统**：选 2 个规模/缺陷率相近的子系统，一个启用协议、一个保持现状（或延迟启用）。
2. **中断时间序列**：启用前后各 8 周，比较水平与斜率变化。
3. **配对变更**：同类变更（同子系统、同规模）在 A/B 两组的处理差异。
4. **消融**：

| 组 | 配置 |
|---|---|
| A | 纯 DSH agent |
| B | A + 技能（无工具/闸门） |
| C | B + 四机制（本地证据 A1） |
| D | C + CI/PR 强制（A2） |

**诚实边界**：样本小、混杂因素多；只报告效应量与方向性，不做强因果断言。

## 五、风险与停止规则

> 本节只保留运行预警，供周会/月会使用；去留与停止以 §3.4 的冻结规则为准。预警阈值不改变指标定义。

| 风险信号 | 触发阈值 | 动作 |
|---|---|---|
| 误拦上升 | >5%（M1）/ >2%（M4） | 查分级/影响分析；修策略 |
| 成本超支 | >2× 预算（预警）；>5× B 且无改善按 §3.4 停止 | 降 L2 配额、缓存、便宜席位 |
| 时延超标 | L1>1d / L2>3d（SLO）；>2d / >5d 升级 | 加评审人、调采样、WIP |
| 绕过 | 例外 >8% 或直接改代码不建工件 | CI 强制 + 团队复盘 |
| 橡皮图章 | >95% 且 <10s | 重设计签字点 |
| 影响漏报 | 2 次同类漏报 | 强制 L2 + 补注册表 |

**停止规则**：C/D 相对 B 在逃逸缺陷率上无 ≥20% 改善 → 停止扩机制；成本 >5× B 且无改善 → 收缩或停止；发布 pilot 数据与方法论。

## 六、go/no-go（M5）

- **继续**：主要指标改善 + 误拦/成本/时延达标 + 团队愿意继续。
- **收缩**：仅保留有效机制（预计 2–3 个），作为轻量版继续。
- **停止**：无改善或成本不可接受；归档代码，发布方法与数据。

## 七、度量采集

- 事件：`.firetree/metrics/events.jsonl`（append-only，每变更一条）。
- 字段：`change_id`、`tier`、`subsystem`、`team`、`tokens`、`duration_ms`、`rounds`、`findings`、`accepted`、`blocked`、`false_block`、`exception`、`signoff_by`、`receipt_valid`。
- 聚合：CI/脚本按周聚合；看板只读。
- 隐私：不含代码内容、密钥、个人信息。

## 八、评审节奏

| 会议 | 频率 | 内容 |
|---|---|---|
| 周会 | 每周 | 指标、误拦、例外、队列 |
| 月度复盘 | 每月 | 策略调整、影响分析漏报、成本 |
| 里程碑验收 | 各阶段末 | 退出条件、演示拒绝、数据 |
| go/no-go | M5 | 继续/收缩/停止 |
