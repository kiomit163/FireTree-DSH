# 设计论纲：为什么是这四个机制

> 这份文件回答三个问题：FireTree V5 到底出了什么问题；为什么不能靠「把 V5 做完」解决；为什么 v1 只做四个机制。

---

## 一、V5 的病灶：六个经典问题的叠加

| 现象 | 经典问题 | 在 V5 里的证据 |
|---|---|---|
| 从 24 个技能膨胀到 17 个 package 的保证系统 | **第二系统效应**（Brooks） | 推理面/保证面/适配器三平面；`packages/` 含 workflow、identity、ccb、evidence、policy、org |
| 在插件里重造事件溯源、RBAC、CCB、签名、策略引擎 | **内在平台效应** | `packages/workflow/events.mjs`、`identity/roles.mjs`、`ccb/`、`evidence/sign.mjs` |
| agent 写证据，agent 的 gate 验证据 | **自证困境**（控制论：观测器=被控对象） | 0 DONE / 67 REVIEW，全部等「外部评审」；A1 自标 |
| 抄航天流程的形式 | **制度同构 / 货物崇拜流程** | 基线、SDR/PDR/CDR、双五条变成字段；真实组织/权限/发布列车不存在 |
| 证据存在成为闸门 | **古德哈特定律** | 「no evidence forgery」补丁；证据文件成为优化目标 |
| 所有变更一套流程 | **未裁剪的质量成本** | 8 镜头 × 7 步 × 5 轮；实测 6× token、13× 时间 |

**核心诊断**：V5 建的是一个**看起来闭合、实际开环**的控制系统。它测到的是「agent 说自己做了」，而不是「系统真的做到了」。

## 二、为什么「做完 V5」不解决

1. **完成定义依赖不存在的东西**：67 个 REVIEW 要求独立评审者，3 个 BLOCKED 要求外部信任基础设施（沙箱、PEP、证据库）。这不是工作量问题。
2. **要删的部分占大头**：17 个 package 里，workflow/identity/ccb/org/signing/board 恰恰是内在平台，做完等于把债还完。
3. **宿主换了**：在 DSH 上，事件日志、工具守卫、权限、调度、技能注册、子代理都是现成的；再维护一套等价物是双倍成本。
4. **没有实证**：0 pilot、0 消融；再多机制也无法回答「它到底有没有用」。

## 三、更优的形态：可审计交付协议

**FireTree-DSH = 协议 + 技能 + 薄插件 + 外部证据。**

六条原则：

1. **外部传感器**：证据由确定性工具/CI 产生，插件只读校验；agent 只能引用。
2. **平台强制**：闸门放在 PR/CI/branch protection，而不是 agent hook。
3. **风险裁剪**：L0/L1/L2 对应不同工件与评审深度，默认低等级。
4. **删除内在平台**：git=事件日志与基线，PR=评审协议，IdP=身份，branch protection=闸门。
5. **单宿主优先**：先把 DSH 做深；核心保持纯函数 + JSON schema，可移植。
6. **可测量**：预注册指标 + 消融 + 发布数据。

## 四、为什么 v1 是这四个机制

选型标准（三条同时满足才进 v1）：

- 能**改变一次工具调用或交付判定**（不是字段）；
- 能产生**可测信号**；
- 有**证伪条件**（什么结果会推翻它）。

| 机制 | 改变什么 | 可测信号 | 证伪条件 |
|---|---|---|---|
| ① 对象辨识门 | OCG 时禁用分解式自治，落到工具/自治等级 | 误分类率、OCG 被分解次数（应恒 0） | 若 OCG 走分解长期无跨层缺陷，门过严 |
| ② 假设台账 | 未绑定检测方式的假设不能进 L2 回执 | 假设检测覆盖率、被证伪数 | 若未绑定的假设从未导致缺陷，降为提示 |
| ③ 综合集成评审 | 多源证据 + 独立席位 + 异议穷尽才收敛 | 跨模型发现重叠率、异议数、收敛轮数 | 若多模型不如单模型，砍掉多模型成本 |
| ④ 再评估 | 决策/证据带时效，过期即阻断并调度重估 | 过期拦截数、重估触发数 | 若从不失效，时效模型错误 |

两条横切：

- **外部证据回执**：回执只能引用 CI/工具证据，agent 不能自签；本地模式显式 A1。
- **人签**：定义好的决策点强制人工；agent 自签计数必须为 0；橡皮图章率超阈值即重设计。

一个测量层（不做闸门，只做观测）：

- 受控变量：WIP、lead time、review latency、escaped defects、rework；周级 SPC。
- 目的：先建立基线，再谈「控制」。没有基线就没有控制论。

**明确不进 v1**：事件溯源引擎、RBAC/角色系统、CCB 运行时、组织模拟（总体设计部/两条指挥线只做工具作用域分离，不做组织仿真）、控制论数学化（传递函数/稳定性证明）、8 镜头默认全开、多宿主适配。

**百万行规模下**：机制的作用域随对象上移（对象辨识到子系统/项目、综合集成只用于跨边界决策、基线到接口、评审分级、再评估按季度）。详见 [QIAN-LANDING.md](QIAN-LANDING.md) §六 与 [SCALE.md](SCALE.md) §2。

## 五、钱学森到底提供什么

不是词汇，不是组织仿真，而是**三样判据**：

1. **先辨识对象，再选方法**：层次不可还原 → 分解会丢要件 → 必须从定性到定量综合集成。
2. **判断必须落到可检验的判据**：经验性假设只有被数据检测后才算结论；「量」必须真实可得。
3. **收敛的判据是异议穷尽**：不是投票、不是一致、不是「看起来可以」；零异议反而是可疑信号。

以及一条组织学底线：**关键处由人决策，重复劳动交给机器**。这条不是能力上限，是对象复杂性的定义性推论。

## 六、设计红线

1. 一个概念若不能改变工具调用 / 产生信号 / 拒绝交付 → 只进文档。
2. 证据生产者 ≠ 被审计 agent；签字人 ≠ agent。
3. 每个机制必须有证伪条件。
4. 归属三分：钱学森原文 / 航天实践 / FireTree 扩展。
5. 没有 pilot 与消融，不扩机制。
6. 不重造宿主已有能力。

## 七、如果只能做一件事

**把「证据来自外部」落地。** 它同时解决自证困境、古德哈特、职责分离三个问题；它是回执、人签、评审、再评估的共同地基。其他机制都可以晚一个版本。
