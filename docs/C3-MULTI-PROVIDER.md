## Review seat CLI

`scripts/opencode-review.mjs` calls one OpenAI-compatible seat and writes a
seat record. It never logs or writes the API key.

```powershell
$env:OPENCODE_GO_API_KEY = '<credential>'
node scripts/opencode-review.mjs `
  --prompt review-prompt.txt `
  --model qwen3.8-flash `
  --diff-sha256 <reviewed-diff-sha256> `
  --out seat-opencode.json
```

The prompt must require JSON:

```json
{
  "verdict": "ready | not-ready",
  "findings": [
    {
      "id": "finding-1",
      "severity": "blocker | non-blocker | question",
      "claim": "...",
      "evidence": "file:line ...",
      "status": "open | resolved"
    }
  ]
}
```

`accepted` is not a seat status. A blocker must be resolved, not accepted, by
a seat. If the model returns `ready` with an open finding, the CLI rejects the
seat instead of writing it.

## Combining seats

For `A3-AI`, combine:

- one `deepseek-account` seat from the host model;
- one `opencode-go` seat from this CLI.

Use the deterministic combiner:

```powershell
node scripts/ai-review-combine.mjs `
  --seat deepseek-seat.json `
  --seat seat-opencode.json `
  --change pr-17 `
  --head <code-head> `
  --diff-sha256 <reviewed-diff-sha256> `
  --author-provider deepseek-account `
  --author-model deepseek-flash `
  --out .firetree/ai-reviews/pr-17.json
```

The combiner validates the artifact before writing it. The seat `provider`
values must differ; otherwise the artifact is only `A3-AI-S`.

The final `firetree.ai-review/v1` artifact must:

- bind `diff_sha256`;
- have zero unresolved findings;
- converge;
- include both provider seat hashes.

Each seat includes its own `context_sha256`, which binds the system prompt,
user prompt, provider, model, and diff digest. Different providers therefore
have distinct context hashes; two seats from the same provider/model and the
same prompt are **not** independent and must not be counted as two contexts.

The current CLI is fixed to `https://opencode.ai/inference/v1`, provider
`opencode-go`, and `OPENCODE_GO_API_KEY`; it cannot be pointed at an arbitrary
endpoint or a different credential reference. Redirects are rejected. The
output path must stay inside `--root`, and an existing symlink at the output
path is rejected.

## Trusted CI path

Production uses `.github/workflows/pr-a3-ai.yml`, not the local seat CLI.

- It runs on `pull_request_target` from the base workflow.
- Trusted base tests run in a separate job with no `id-token: write`.
- The review job checks out only trusted base code, fetches the PR head as
  data, and computes the diff.
- The review is generated by `scripts/trusted-ai-review.mjs` with:
  - `opencode-go` / `glm-5.3-flash` with `OPENCODE_GO_API_KEY`;
  - `pollinations` / `openai` via the keyless public endpoint;
  - `FIRE_TREE_REVIEW_SIGNING_KEY` for the HMAC signature.
- The generated artifact is HMAC-signed and placed in `.firetree` only after
  generation; the PR cannot supply it.
- `firetree-check --require A3-AI` verifies the HMAC before accepting it.
- The required check context is `firetree-a3-ai`.

The local `opencode-review.mjs` / `ai-review-combine.mjs` path remains useful
for manual audit and debugging, but it is not the production gate.

The Pollinations seat is a public anonymous endpoint. It is independent of
OpenCode, but it has no data-retention contract; do not use this workflow for
sensitive repositories until the second provider is replaced by an
operator-controlled endpoint.

## Security boundary

This CLI is a seat generator, not a trusted decision-maker. The decision is
only `A3-AI` when:

1. at least two distinct provider routes participate;
2. the review artifact is inside the attested bundle;
3. `firetree-check` verifies it with `--require A3-AI`;
4. the PR cannot supply the review itself in production mode.

Until the review service runs outside the PR author's control, this remains a
machine-assisted review path, not an independent third-party audit.
