## D1 产品身份：可审计交付协议

- 状态：ACCEPTED
- 日期：2026-11-06
- 授权方式：用户直接开工指令（会话授权，2026-11-06），按 KICKOFF 推荐项 B 采纳。
- 主持人 / 记录人：用户（授权）/ lead engineer（agent，记录）。
- 规模含义：目标为单仓 10k–50k 文件、1M–5M LOC、3–5 个团队、50–500 PR/周。协议必须在「不读全库」的约束下运行，靠注册表、变更集与外部证据工作。
- 决定：FireTree-DSH 是「协议 + 技能 + 薄插件 + 外部证据」，不是治理 OS；v1 不自带工作流引擎、RBAC、CCB、签名服务或证据库。
- 背景：V5 一半病灶来自内在平台（工作流引擎、RBAC、CCB、签名、证据库）。
- 选项与代价：
  - A. 治理 OS：自带运行时（代价：维护成本高、与宿主重复、难以审计）。
  - B. 交付协议：借 DSH/CI/组织（代价：放弃一站式卖点、需集成、无 CI 时只能 A1）。
- 采纳代价：放弃「大组织控制面」的叙事；跨系统集成成本由使用方承担；本地模式无法声称 A2。
- 理由：协议可验证、可替换、可审计；DSH 已提供运行时原语。
- 证伪条件：pilot 显示团队执行率 <60%（缺内置工作流导致协议跑不起来）→ M4 复议最小运行时。
- 复议时间：M4 复盘。
- 红队反对意见与回应：T0.7 补录；未补录不得视为红队完成。

- 理由：信任根必须移出 agent 的写作用域。
- 证伪条件：若本地 A1 模式下缺陷逃逸与 CI 模式无差异，可放宽对 CI 的依赖。

- 理由：先把一个宿主做深，再谈移植；协议层可复用。
- 证伪条件：DSH 缺少关键原语或 API 不稳定导致无法交付 → 重新评估宿主。
