# 决策记录（ADR）

> 规则：**没写进这里的决定不算数。** 每条决定必须包含代价、证伪条件、复议时间；没有这三项的决定视为未完成。
> 状态：`PROPOSED`（会前草案）→ `ACCEPTED`（会上定稿）→ `SUPERSEDED` / `REVISITED`。

## D1 产品身份：可审计交付协议

- 状态：PROPOSED
- 决定：FireTree-DSH 是「协议 + 技能 + 薄插件 + 外部证据」，不是治理 OS。
- 背景：V5 一半病灶来自内在平台（工作流引擎、RBAC、CCB、签名、证据库）。
- 选项：
  - A. 治理 OS：自带运行时（代价：维护成本高、与宿主重复、难以审计）。
  - B. 交付协议：借 DSH/CI/组织（代价：放弃一站式卖点、需集成）。
- 理由：协议可验证、可替换、可审计；DSH 已提供运行时原语。
- 证伪条件：pilot 显示团队执行率 <60%（缺内置工作流导致协议跑不起来）→ M4 复议最小运行时。
- 复议时间：M4 复盘。

## D2 v1 机制集：四机制 + 两横切 + 一测量层

- 状态：PROPOSED
- 决定：
  - 四机制：对象辨识、假设台账、综合集成评审、再评估。
  - 两横切：外部证据回执、人签。
  - 一测量层：受控变量（WIP/lead time/escape/rework），只观测不闸门。
- 背景：V5 有 10 个概念、0 个实证；概念数量是深度敌人。
- 选项：
  - A. 全量迁移 10 个概念（代价：浅、重、无法验证）。
  - B. 四个做透（代价：其余概念只进文档）。
- 理由：每个机制都能改变工具调用/拒绝交付/产生信号；其余暂不配代码。
- 证伪条件：四机制中任一在 pilot 中从未改变决定 → 删除该机制。
- 复议时间：M4。

## D3 证据根：CI/工具产生，插件只读

- 状态：PROPOSED
- 决定：evidence 的 `producer` 不得为 agent；插件只校验哈希与来源。本地模式显式标记 A1，不得声称 A2。
- 背景：自证困境（观测器=被控对象）是 V5 的核心缺陷。
- 选项：
  - A. agent 生成证据 + 插件验签（代价：信任仍来自被审计方）。
  - B. 外部生成 + 插件只读（代价：无 CI 时只能 A1）。
- 理由：信任根必须移出 agent 的写作用域。
- 证伪条件：若本地 A1 模式下缺陷逃逸与 CI 模式无差异，可放宽对 CI 的依赖。
- 复议时间：M3。

## D4 人签与角色：决策点强制人工

- 状态：PROPOSED
- 决定：L2 定稿、风险接受、OCG 方法选择、接口基线变更必须人工签字；agent 自签计数恒为 0。
- 背景：「敢签字」是责任机制，不是流程装饰。
- 选项：
  - A. 全自动（代价：责任无人承担，审计不可信）。
  - B. 关键点人工（代价：增加等待）。
- 理由：钱学森原文的「人机结合、以人为主」是对象复杂性的推论，不是能力上限。
- 证伪条件：人签从未改变任何决定（橡皮图章率 >95% 且 <10s）→ 改为抽样审计 + 责任声明。
- 复议时间：M4。

## D5 宿主策略：v1 只做 DSH

- 状态：PROPOSED
- 决定：v1 只实现 DSH 插件；核心 `lib/` 保持纯函数与 JSON schema，可移植；不写多宿主适配层。
- 背景：V5 三个半支持宿主是负资产；DSH 提供 guard/approval/schedule/subagents 等关键原语。
- 选项：
  - A. 多宿主抽象（代价：每个都浅、成本×3）。
  - B. DSH 单宿主（代价：短期用户面窄）。
- 理由：先把一个宿主做深，再谈移植；协议层可复用。
- 证伪条件：DSH 缺少关键原语或 API 不稳定导致无法交付 → 重新评估宿主。
- 复议时间：M3。

## D6 迁移策略：新仓重写，V5 归档

- 状态：PROPOSED
- 决定：新仓库重写；V5 打 tag `v5-archive`；只迁内容与纯函数，不迁运行时。
- 背景：V5 完成定义依赖不存在的外部评审者（0 DONE/67 REVIEW）。
- 选项：
  - A. 渐进改造 V5（代价：在错误架构上还债）。
  - B. 新仓 + 内容迁移（代价：丢弃 100 任务中的运行时部分）。
- 理由：要删的内在平台占大头；宿主已变。
- 证伪条件：迁移后 M1 延期超过 4 周 → 回退到「V5 只保留文档、代码冻结」的轻方案。
- 复议时间：M1 末。

## D7 度量与消融：预注册 + A/B/C/D

- 状态：PROPOSED
- 决定：指标在 M0 冻结；pilot 采用 A（纯 agent）/B（+技能）/C（+机制）/D（+外部证据）四组；12 周内出数据。
- 背景：V5 无 pilot、无消融，机制无法证伪。
- 选项：
  - A. 先做再说（代价：结果不可信）。
  - B. 预注册 + 消融（代价：需要 6–8 周 pilot）。
- 理由：没有数据不扩机制。
- 证伪条件：若 C/D 相对 B 无改善（阈值见 ROADMAP）→ 停止扩机制或收缩。
- 复议时间：M4。

## D8 发布形态：DSH bundle + 一条命令

- 状态：PROPOSED
- 决定：以 DSH bundle 发布（`plugin_manager install_bundle`）；许可证建议 Apache-2.0；保留 BMAD/superpowers 的 MIT NOTICE；不发布钱学森原文。
- 背景：V5 的 install.mjs 与三宿主清单不可持续。
- 选项：
  - A. 多形态发布（npm + 手动 + 市场）（代价：维护面大）。
  - B. 单一 bundle（代价：依赖 DSH 生态）。
- 理由：分发不是差异化；先把协议做对。
- 证伪条件：DSH 插件生态不足以触达目标用户 → M4 后评估第二分发渠道。
- 复议时间：M4。
