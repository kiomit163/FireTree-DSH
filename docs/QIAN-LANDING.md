# 钱学森精髓的落地矩阵

> 目标不是「引用钱学森」，而是把他的**判据**变成 DSH 里**能改变工具调用、能产生信号、能被证伪**的机制。
> 本文件是 v1 的设计依据；改动任何 Qian 派生机制，必须引用本文件并说明归属。

---

## 一、结论先行

| 层 | V5 现状 | 本项目目标 |
|---|---|---|
| 文本层（引文/出处/归属） | A−（引文真实、归属诚实） | 保持，并补可复现的引文台账 |
| 概念映射层 | B（10 个概念→字段/步骤） | 收敛到 4 个机制，其余进文档 |
| 机制层（可执行可拒绝） | C+（约 4 个真落地） | 把 4 个做到「能拒绝交付」 |
| 动力学层（控制论） | D（只有比喻） | 先建受控变量与基线，不追求数学化 |
| 实证层 | 未开始 | pilot + A/B/C/D 消融，12 周内出数据 |

**一句话**：V5 把最容易抄的航天实践做深了，把钱学森最难的部分留成了 schema。本项目反过来——**少而深，先做那三个真正属于钱学森、且 DSH 第一次能执行的判据。**

## 二、语料与核验方法

- 语料：`D:\Qian` 四卷 DOCX，抽取正文约 **136 万汉字**（卷1 23.6万 / 卷2 39.9万 / 卷3 39.8万 / 卷4 32.8万）。
- 核验：抽取脚本 + 四卷 SHA-256 + 20 条关键引文子串核验（见 [reference/qian/quotes.md](../reference/qian/quotes.md)）。
- 结论：**引文真实存在，且归属与 V5 标注一致**；但 R1）逐字研读台账在 V5 已丢失，R2）设计所依赖的《工程控制论视角下的 AI Coding 质量保障体系》不在语料中。本项目重建 R1，R2 从论证链中移除或补来源。

**词频揭示的结构性错配**（详见 quotes.md）：

| 概念 | 卷1 | 卷2 | 卷3 | 卷4 | V5 机制化 |
|---|---|---|---|---|---|
| 综合集成 | 9 | 9 | 250 | 466 | 低（字段 + 计划中引擎） |
| 复杂巨系统 | 3 | 3 | 459 | 188 | 中（分类门） |
| 从定性到定量 | 0 | 1 | 131 | 144 | 低（标签） |
| 总体设计部 | 1 | 38 | 128 | 40 | 名义（字段/Board） |
| 评审 | 0 | 2 | 4 | 16 | 高（但主要出自卷4实践章） |
| 基线/技术状态/双五条 | 0 | 0 | 0 | 8/5/1 | 高（但属航天实践） |

**推论**：出现最多的概念被做得最浅，机制最深的来自钱学森原文最少的实践章节。本项目不再扩大这种错配。

## 三、四条翻译规则（防止二次沦为修辞）

1. **只迁移判据，不迁移本体论**。OCG 是「先判断能不能分解」的判据，不是给软件子系统贴的分类学标签。
2. **只迁移可拒绝的机制**。一个概念如果不能改变一次工具调用、不能拒绝一次交付，就不进代码。
3. **只迁移控制结构，不迁移数学**。反馈、时滞、增益、阈值、冗余可以借；传递函数、稳定性证明不借（V5 已声明，本项目收紧为红线）。
4. **每个机制必须有证伪条件**。写不出「什么结果会让我们反悔」，就不进 v1。

## 四、落地矩阵

### Q1 对象辨识：先判能不能分解（**v1 核心**）

- **原文判据**（卷3）：层次很多且中间层不认识时，还原论分解会丢要件——「从可观测的整体系统到子系统，层次很多，中间的层次又不认识」；「你把它一分解，要紧的东西都跑了」。另有边界（卷2）：「大系统控制论是不能直接用来解决巨系统问题」。
- **不迁移**：不把软件子系统硬套成 OCG；不引入「宏观观察/微观还原」的物理语义。只借用**一个问题**：这次变更的层次与耦合，是否可枚举、可分解验证？
- **DSH 机制**
  - 工具 `firetree_classify`：产出 OID dossier（`kind`、`layers_known`、`layers_unknown`、`coupling_evidence`、`reducibility_test`、`method`、`owner_of_unknowns`、`learning_plan`）。
  - `ctx.tools.guard`：当 dossier 判定为 `open-complex-giant` 或 `unknown`，**同步拒绝**分解式自治交付（如批量自治执行、无人工签字的回执定稿）。
  - `systemPrompt.section`：只给一句路由，正文在技能里按需加载。
- **工件**：`.firetree/oid/<subsystem>.json`，随 PR 提交，可评审。
- **可测信号**：误分类率；`OCG × 分解` 次数（目标恒 0）；`unknown_layers` 无 owner 数（目标 0）。
- **证伪条件**：连续 10 次 OCG 走分解路径且无跨层缺陷 → 门过严，降级为提示。
- **判定逻辑**：`layers_unknown` 非空或 `reducibility_test` 失败 → 不得声称 `reducible`；降级为 `unknown` 并进入综合集成路径。

### Q2 从定性到定量：假设必须被数据检测（**v1 核心**）

- **原文判据**（卷3）：经验性假设「不能用严谨的科学方式加以证明，往往是定性的认识，但可用经验性数据和资料以及……模型对其确实性进行检测」；「这个『量』……是实实在在的数字……不是人为的」。反面即「凭数算命」。
- **不迁移**：不要求每个判断都建数学模型；不把「定量」等同于覆盖率数字。
- **DSH 机制**
  - 工具 `firetree_hypothesis`：`add` 必须给 `detection{method, command, pass_criterion, evidence_kind}`；`verify` 必须给外部证据引用；`list` 输出覆盖率。
  - 回执校验：L1/L2 变更存在 `untested` 假设时，`firetree_receipt` 拒绝定稿（除非人工签字接受风险 + 到期日）。
- **工件**：`.firetree/specs/<slug>/hypotheses.json`。
- **可测信号**：假设检测覆盖率；被证伪数；带证据通过的假设数。
- **证伪条件**：未绑定检测的假设从未与缺陷相关 → 降为提示，不做门禁。

### Q3 综合集成：多源证据 + 独立席位 + 异议穷尽（**v1 核心**）

- **原文判据**（卷3，转述）：综合集成的方法要素包括专家经验判断、客观实际数据、以及把两者综合起来的模型/系统方法；收敛靠「改得你说不出意见来了」；差异度是研讨的质量指标（卷4）：「差异性程度排名靠前……有更多的与众不同的关注点」。
- **不迁移**：不把 JSON 表单叫「研讨厅」；不假装单模型多提示词就是多专家。
- **DSH 机制**
  - 工具 `firetree_synthesize`：`plan` 生成席位与输出 schema；`record` 校验一轮结构化结果并计算差异度/重叠率/收敛状态。
  - 席位独立性：至少两个席位使用**不同 provider/model**（DSH `subagent` 支持 provider/model 覆盖），上下文隔离；数据席位必须给出可复现命令与数值；经验席位给判断与依据。
  - 综合器必须逐条回应异议（接受/驳回 + 证据），一轮无新异议才收敛。
  - `workflow` 工具用于脚本化多轮扇出（不是自研引擎）。
- **工件**：`.firetree/changes/<change>/{package.json, round-N.json, verdict.json}`（结构化发现 + 异议 + 回应）。
- **可测信号**：跨模型发现重叠率；每轮新异议数；收敛轮数；被证据驳回的异议比例。
- **证伪条件**：多席位相对单模型在评审精确率/逃逸率上无显著改善 → 砍掉多模型成本，保留单模型 + 七步。

### Q4 评审是过程，收敛靠异议穷尽（**v1 核心，与 Q3 合并实现**）

- **原文判据**（卷4，郭宝柱）：评审是各层次上的**过程**而非单独事件；七步：准则、数据、人选、会前独立研究、会上充分讨论、**书面结论**、会后告知。
- **不迁移**：不模拟评委会；不把「开会」搬进插件。七步落成**可检查的工件序列**。
- **DSH 机制**：`firetree_review` 的 `open/round/verdict` 三动作；缺任一步拒绝 verdict；零异议轮要求自证「查过什么」；L2 需要外部签字。
- **可测信号**：每轮新发现数曲线；步骤完整率；零异议率（异常高即告警）。
- **证伪条件**：三步评审与七步评审的逃逸率无差异 → 裁剪步骤。

### Q5 再评估：解答有时效（v1 轻量，M3 完整）

- **原文判据**（卷3）：「任何一次解答都不可能是一劳永逸的，它只能管一定的时期」。
- **DSH 机制**：决策/证据带 `expires_at` 与 `reval_trigger`；过期 → `firetree_state` 标红、回执拒绝；`schedule_create` 周期触发重估。
- **信号**：过期拦截数；重估触发数。
- **证伪条件**：一年内没有任何条目过期 → 时效模型不真实，改为事件触发。

### Q6 人机结合 + 敢签字（**v1 横切**）

- **原文判据**（卷3）：「如果完全靠机器能解决问题，那就不是开放复杂巨系统」；「让计算机伺候人」；「你敢不敢签字，我按你说的理论方法去下决心干，出了问题我可是要问你的」。
- **DSH 机制**：决策点用 `approval` / `ask_user_question` 强制；签字来自 CI 身份或人，**agent 自签计数恒为 0**；回执记录签字人与后果声明。
- **信号**：自签数（0）；人工等待时长；橡皮图章率（>95% 且 <10s 即重设计）。
- **证伪条件**：人签从未改变任何决定 → 改为抽样审计 + 责任声明。

### Q7 两条指挥线 / 总体设计部（**只做作用域映射，不做组织仿真**）

- **原文判据**（卷2/卷3）：技术指挥与调度指挥各有专职；总体设计部不承担具体部件设计，但对总体一致性负签字责任。
- **不迁移**：不建 Board、不建角色系统、不模拟「几百人」；一个人不能在插件里变成两个人。
- **DSH 机制（v1 可选）**：用 `tools.restrict` / `ctx.tools.guard` 做**工具作用域**：架构视角只读（禁 edit）、技术线可写、调度线不碰代码；接口一致性由只读架构代理出回执。规模上，评审人与 owner 直接映射 CODEOWNERS，签字映射到 CI OIDC/人，不自建身份系统。
- **信号**：越权尝试被拒数；接口漂移数；CODEOWNERS 覆盖率。
- **证伪条件**：单一作用域与分离作用域的质量无差异 → 不做分离，只保留只读架构评审。

### Q8 基线与技术状态控制（**航天实践，明确归属**）

- **来源**（卷4，郭宝柱/郑宝煊等）：基线是某层次完成后的状态描述；上级基线稳定受控后下级才开工；更改是申请-评估-批准的受控程序。
- **不迁移**：不自研 CCB 运行时；不把字段当审批；不做全库快照。
- **DSH 机制**：git commit/tag + CI 证据 + **接口基线**（接口注册表 + 契约测试 + consumers）+ 回执中的 `impact_traversal`；未列入影响的变更不能定稿。
- **规模行为**：基线的作用域是**接口/发布**，不是目录；接口变更 → L2 + 影响遍历 + 人签。
- **信号**：影响遍历覆盖率；未批准变更数（0）；接口契约测试通过率。
- **证伪条件**：影响遍历漏报率高于人工基线 → 简化或改为可选。

### Q9 工程控制论（结构层，只做观测，不做数学）

- **原文判据**（卷1）：反馈、稳定性、可控可观；V5 已声明只到结构层。
- **本项目**：**v1 不做闸门**，只建测量——受控变量：WIP、lead time、review latency、escaped defects、rework；周级 SPC（控制图/越界告警）。
- **证伪条件**：受控变量与逃逸缺陷无相关性 → 放弃控制论叙事，只保留指标看板。

## 六、百万行规模下的作用域上移

钱学森的对象是**系统**，不是零件（卷2：「总体设计部一般不承担具体部件的设计，却是整个系统研制工作中必不可少的技术抓总单位」）。百万行项目里，如果把判据用在文件/单次提交上，就会重演「一分解，要紧的东西都跑了」。因此：

| 机制 | 小项目作用域 | 百万行作用域 | 钱学森依据 |
|---|---|---|---|
| 对象辨识 | 每个变更能否分解 | **子系统/项目**能否分解；OCG 判定 | 层次不可还原 → 分解丢要件 |
| 假设检测 | 每个设计假设 | 变更级 + 架构决策级；L2 抽样验证 | 经验性假设须被数据检测 |
| 综合集成 | 每个评审 | **跨子系统/接口决策**才多席位 | 复杂巨系统才需要综合集成 |
| 评审七步 | 每个变更 | L2 七步 / L1 三步 / L0 采样 | 评审是过程，按对象裁剪 |
| 基线 | 每次提交 | **接口基线 + 发布基线** | 上级基线稳定后下级才开工 |
| 再评估 | 每个决策 | 接口/ADR/程序基线按季度 | 解答只在一定时期有效 |
| 人签 | 每个定稿 | 接口 owner / 架构师；L2 定稿 | 关键处由人决策 |

**三条规模推论**

1. **分类在系统层，执行在变更层**：`firetree_classify` 管子系统/项目；`firetree_assess` 管每次变更。不要把 OCG 判定塞进每个 PR。
2. **综合集成是稀缺资源**：只在 L2（跨边界）触发，有配额、有时间盒；否则会退化成「每个 PR 都开研讨会」。
3. **基线是接口，不是目录**：接口契约 + 契约测试 + consumers 才是可控制的「技术状态」；目录/文件基线在百万行里没有意义。

**反模式**：把「总体设计部」做成字段、把「研讨会」做成每个 PR 的固定步骤、把「基线」做成全库快照——都是在零件层做系统层的事。

## 八、去装饰化审计：哪些是真结合，哪些只是框架

判断标准（三问）：

1. 它改变一次工具调用或交付判定吗？
2. 它产生一个可测信号吗？
3. 它有证伪条件吗？

三问全过 = **机制**；只过 2 = **判据**；只过 1 = **隐喻**；一问不过 = **误用/删除**。

| 映射 | 类型 | 判定 | 处理 |
|---|---|---|---|
| 对象辨识 → `firetree_classify` / `assess` | 机制 | 三问全过；直接改变工具与自治等级 | **保留（核心）** |
| 假设检测 → `firetree_hypothesis` + 回执绑定 | 机制 | 未检测假设拒绝定稿；覆盖率可测 | **保留（核心）** |
| 异议穷尽 → 轮次台账 + 零新增收敛 | 机制 | 缺轮次/零异议无自证即拒绝 | **保留（核心）** |
| 再评估 → 过期 + 调度 | 机制 | 过期阻断；重估可测 | **保留（核心）** |
| 人机结合/敢签字 → approval + 外部签字 | 机制 | 自签恒 0；等待时长可测 | **保留（横切）** |
| 综合集成 → 多模型独立席位 | 机制+判据 | 独立性/差异度可测；但「专家=模型、数据=工具」是**类比**，不是等价 | 保留，**明确标注类比**，不叫「研讨厅」 |
| 基线/技术状态 → 接口基线 + 影响遍历 | 判据 | 影响召回可测；但归属是**航天实践**，不是钱学森原文 | 保留，**归属更正** |
| 两条指挥线 → 工具作用域分离 | 隐喻 | 改变的是权限卫生，不是两条指挥线；无独立证据 | **降级：文档可选，不做代码默认** |
| 总体设计部 → 只读架构代理 | 隐喻 | 一个只读 agent 不是「常设实体」；无法验证 | **降级：文档 only** |
| 工程控制论 → 受控变量 + SPC | 隐喻 | SPC 主要来自 Shewhart/Deming；借结构可以，冠名 Qian 是归属膨胀 | **只留测量，去掉 Qian 冠名** |
| 双五条 → 缺陷归零清单 | 误用 | 航天质量实践，代码层不适用；原文仅出现 1 次 | **不迁移，文档备注** |
| 四台阶 → 方法论定位 | 判据 | 帮助定位「工程技术台阶」，不产生行为 | 文档保留 |

**诚实结论**

- 真正承重的是 **5 条判据**：对象辨识、假设检测、异议穷尽、再评估、人机签字。它们即使不署钱学森的名字也成立，但钱学森提供了明确的判据形式与边界。
- **综合集成**是「有条件的类比」：独立席位、多源证据、收敛确实有用；但把模型叫专家、把流程叫研讨厅，是过度类比。
- **基线/技术状态**是工程骨架，但归属是航天实践；拿它给「钱学森」贴金是归属错误（V5 已标注，本项目继续守这条线）。
- **两条指挥线、总体设计部、工程控制论**目前是框架/隐喻；放进代码会变成组织仿真或归属膨胀，已降级。
- **正确性论证（correctness case）**：Q2（假设检测）与 Q6（签字担责）的合流，属 FireTree 扩展；它把「凭什么说对」写成 claims→invariants→evidence→residual，不冠 Qian 名。
- **如果去掉「钱学森」三个字，协议仍然成立**——这恰恰说明工程核心是独立的；钱学森是判据来源，不是装饰层。

## 九、不做什么（反面清单）

1. **不做组织仿真**：不建 Board/角色/评委会；要么真实权限，要么只做工具作用域。
2. **不做控制论数学化**：不写传递函数、稳定性证明；只借结构。
3. **不把 JSON 当研讨厅**：没有独立席位与真实数据，就不是综合集成。
4. **不把字段当机制**：新增字段前先回答「它改变哪次调用、产生什么信号、如何证伪」。
5. **不把「钱学森说」当论据**：论据是可测信号与证伪条件。
